Accessibility

Access should not depend on sight.

JamScan aims for WCAG 2.2 Level AA where the project can reasonably apply it. The visual camera stream is optional; every package can also be shared and opened as a normal .jscan file.

What is included

  • Keyboard-accessible navigation, controls, drop areas, dialogs, and file opening.
  • Visible keyboard focus and high-contrast text and controls.
  • Semantic headings, landmarks, labels, status regions, and a skip link.
  • Reduced-motion support and no automatic visual-stream playback.
  • A 3 frames-per-second maximum and a warning before the stream starts.
  • A nonvisual .jscan file route for people who cannot use the camera stream.
  • No important instruction is communicated by color alone.

Known limitation

The camera-based stream is visual by nature and cannot be independently operated by a person who cannot see the other display or camera framing. The equivalent accessible route is to save, send, and open the .jscan file directly.

JamScan does not claim that this statement or automated checks guarantee legal compliance. Real accessibility work should include manual keyboard testing, screen-reader testing, zoom testing, color-contrast review, and feedback from disabled users.

Suggested test routine

  1. Use only Tab, Shift+Tab, Enter, Space, arrow keys, and Escape.
  2. Test at 200 percent browser zoom and with a narrow mobile viewport.
  3. Test with a screen reader such as NVDA, VoiceOver, or TalkBack.
  4. Turn on reduced motion, high contrast, and forced-colors modes.
  5. Confirm that Make, Open, and all warning dialogs work without a mouse.
  6. Ask disabled testers to report barriers through the repository issue tracker.

Report a problem

Open an issue in the project repository with the page, browser, device, assistive technology, expected result, and what happened. Do not include private file contents.
